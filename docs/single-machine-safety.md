# 单机安全与维护

这些功能借鉴安全边界与运维设计，不替换现有 Edge、OAuth、人工接管或私人站点规则。不需要 NAS、数据库服务或新增依赖。

## 精确书签范围

在被 Git 忽略的 `config/config.local.json` 中增加选择器，再按已有配置生成流程更新本机运行配置。例如：

```json
{
  "containerFolderSelectors": [
    { "path": ["书签栏", "示例任务"] }
  ]
}
```

也可使用 `{ "id": "123" }` 或 `{ "guid": "示例目录 GUID" }`。多个字段为 AND，多个选择器为显式目录并集；每个必须唯一匹配。完整路径推荐数组格式，避免目录名称包含分隔符的歧义。目标子目录仍由原有 `targetFolderNames` 限定，每个来源可以覆盖选择器。

精确范围下不会使用书签备份，也不会在可选来源失配时静默扩大范围。移动或删除目录、同步改变 ID/GUID 时需要重新确认范围。未启用选择器的旧配置保持兼容，不自动改写浏览器书签。

## 证据与动作隔离

V2 证据包含站点 origin、匿名 `accountKey`、实际观察 origin、`actionType`、周期 ID 和原始确认时间。它不保存网站真实账号 ID、余额、Cookie 或 Token。验证器拒绝跨站点、跨账号、跨动作、跨周期和不允许来源的证据。旧证据保留兼容，但展示时不把缺少证据的成功状态补判为权威确认。

`data/submission-journal.json` 只在本机保存提交意图、状态和追加核验历史；不随代码发布。已开始但未确认的动作会保持隔离，同周期权威证据才能解除。跨日、重新登录、清理运行日志和用户规则均不会自动解除；原周期缺少可只读确认的信号时继续要求人工核验。不要通过删除记录强行重试，网站上的原操作并不会因此撤销。

普通页面提交、New API POST、原生动作及重新认证退出前写入意图。协议明确拒绝提交可以记录为 `rejected`，而超时、响应丢失或窗口关闭不能证明未提交。尚未支持的旧适配器若报告 `submissionAttempted`，也会进入持久隔离。访问本身会产生奖励的规则在隔离中不再打开页面，以免所谓只读核验又产生动作。

权益抽取等多步规则各自持有提交记录。步骤支持明确、稳定的 `actionType`；未填写时由步骤网址和按钮文本生成匿名哈希，单纯调换步骤顺序不会混用记录。变更动作定义前需检查旧动作是否仍有不确定提交，不能靠改标识绕过隔离，也不能把“登录成功”当作权益已到账。任何新适配器都必须先补提交边界和权威复核测试。

## 共享状态合同与只读历史

修改 `shared/checkin-contract.json` 后执行：

```powershell
rtk npm run contract:generate
rtk npm run contract:check
rtk npm test
```

生成的 JS/PowerShell 文件必须随代码一起分发。错误码未列入分类表时仍保留原码，不据此补判成功。

运行 `rtk npm run status` 生成 `outputs/status.html`。它读取最新结果、每日历史摘要和最多 200 个本地运行目录，展示最近 31 天的每日、账号维度统计；只读、有内容安全策略、不加载外部资源。旧日报可能仅有部分证据，这会显示为证据不完整，而不是伪造历史。最终日报自动归档纯计数摘要到忽略的 `data/status-history.json`，最多 180 天；清理运行日志不会删除已归档摘要。同日定向补跑不能用不完整报告缩减完整日统计，摘要损坏时尝试 `.previous` 版本，没有有效备份则保留坏文件并读取原始日志。归档失败只提示，不触发重新签到。

状态及故障标签、未开放证据白名单共用 JS/PowerShell 合同。全部任务与可执行任务的权威完成率分开展示；后者仅排除经过证据核验的未开放任务和明确跳过任务，站点故障、缺项、未确认声明不会被隐藏。昨天、未来或超过 26 小时的报告提示时间异常，各站点周期证据独立检查。页面原子发布失败时保留旧快照。真实账号身份、凭证和余额不进入 HTML。

## 普通 New API 账号与日期核验

HTTP、页面内请求和原生 CDP 使用同一协议。签到前核验当前账号，成功后再次核验；提供日历的接口必须有且仅有一条业务日期记录，记录的账号（若提供）一致，奖励字段为有限非负值。请求响应丢失后仅做有限只读回查，不发送第二次 POST。证据不一致或账号变化时保留未确认状态。

普通布尔状态接口仍兼容。需要更严格的站点可在忽略的 `config/config.local.json` 中加入规则，并沿用既有配置生成流程更新运行配置；以下均为虚拟示例，不能直接套用到私人站点：

```json
{
  "newApiAccountRules": {
    "https://api.example": {
      "expectedAccountId": "12345",
      "requireCalendarRecord": true
    }
  }
}
```

真实账号 ID 只用于私有配置和同源请求头，不写入报告或回执。强制日历模式在缺少日历时停止提交，接口失效时不能使用页面文字替代严格证据；不支持日历的站点应省略该选项。业务日期来自 `siteCycleRules` 的周期起始日期，配置前须确认它符合站点接口日期约定。这套规则适用于普通 `/api/user/checkin`，专用验证码、Bearer、`sign_in` 和重认证适配器保留各自协议。

## PT 严格被动核验（按站点启用）

以下私有规则只读取经过确认无副作用的每日状态页面，不适用于“访问即领取”的入口：

```json
{
  "ptPassiveReadRules": {
    "https://pt.example": {
      "url": "/index.php",
      "selector": "#daily-status",
      "authenticatedSelector": "a.logout",
      "signedTextPattern": "{date} 已签到",
      "unsignedTextPattern": "{date} 未签到"
    }
  }
}
```

规则要求同源 HTTPS、无查询参数的被动页面，拒绝已知动作路径和重定向。使用既有隔离会话发送一次 GET；返回的 HTML 在无凭据的新上下文中解析，关闭脚本、Service Worker、下载，并阻断其他导航及子资源。只接受唯一状态区和可见登录确认控件，当前日期的已签到与未签到信号必须互斥。未确认、重定向、登录失效或解析器不可用时停止，不自动绕回动作页；明确未签到且不是只读运行时，才继续原有签到流程。

日期通过 `{date}` 替换为业务日期。没有日期的每日页头信号必须经用户确认该站点语义后显式设置 `dailyHeader: true`；默认不启用，不把普通“签到入口消失”作为权威完成。静态页面依赖外部样式或脚本、缺少可见登录控件时可能无法核验，应调整专属规则或继续使用原流程。

## 持久确认回执

本机提交日志在权威完成后保存精简回执，绑定站点、匿名账号、动作、周期和隔离 Profile 的哈希；不保存 Profile 路径、真实 ID、页面内容或奖励。私人 `reuseConfirmedSubmissionReceipts: true` 可在同周期重启后跳过已有回执的动作，默认关闭。复用保留原始观察时间，只表示原动作已确认，不表示刚刚重新读取了网站。

存在未确认提交、跨周期、切换 Profile/浏览器/匿名账号或变更相应私有核验规则时不能复用；用户规则不会生成权威回执，也不能解除提交隔离。显式只读运行、普通 New API 和顺序动作始终做实时核验。此选项仅适用于每账号固定隔离 Profile；在同一 Profile 内退出或换账号时应保持关闭并重新核验，路径哈希无法检测浏览器内的账号切换。

## 代码更新与回滚

工具只处理明确列出的公共代码路径，不下载软件、不切分支、不修改本机设置。准备可信的旧代码目录和候选代码目录后：

```powershell
rtk npm run release -- build outputs/release-demo --baseline <旧代码目录> --candidate <候选代码目录> --files src/example.mjs,README.md
rtk npm run release -- preview outputs/release-demo
rtk npm run release -- apply outputs/release-demo --confirm
```

构建记录每个文件的前后 SHA-256；预览和应用都检查代码漂移与包内容哈希。仅允许选定的代码/文档目录及根级公共文件，拒绝路径穿越、符号链接/目录联接、私人配置和运行文件。发布前仍须运行公开安全扫描，哈希一致不代表代码可信。当前简化版不发布文件删除和依赖安装。

应用占用签到运行锁，拒绝未完成人工接管，先在 `data/code-update-backups/` 备份代码；异常时恢复本次已修改的文件。正常回滚须先预览返回的备份路径：

```powershell
rtk npm run release -- preview <返回的备份目录> --rollback
rtk npm run release -- rollback <返回的备份目录> --confirm
```

回滚只接受此次更新哈希或原始哈希；中断更新时尚未替换的文件会保留原样，便于恢复部分更新。若用户已经继续编辑成其他内容，停止并提示漂移。回滚会删除该更新新建且哈希仍一致的代码文件，但不删除任何配置、Profile、日志或提交隔离记录。网站上的签到、领取和抽取不能通过代码回滚撤销。
